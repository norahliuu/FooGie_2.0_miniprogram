# 「食谱提取」微信小程序 — MVP需求文档 & 技术方案

## 一、产品概述

**产品名称**：食光机

**一句话描述**：粘贴小红书/抖音/B站的菜谱视频链接，自动提取食材清单和分步骤教程，支持做饭模式逐步跟做。

**目标用户**：喜欢刷社媒学做菜的厨房新手，几十到几百人规模的自用/朋友间分享工具。

**商业模式**：暂无，纯个人工具，不追求商业化。

---

## 二、功能需求（MVP范围）

### 2.1 核心功能：链接解析

**用户操作**：在输入框粘贴一个视频链接，点击"解析"按钮。

**支持平台**：
- 小红书（xhslink.com / xiaohongshu.com）
- 抖音（douyin.com / v.douyin.com）
- B站（bilibili.com / b23.tv）

**系统处理流程**：
1. 识别链接所属平台
2. 调用视频解析API，获取视频文件地址 + 视频文案/描述文字
3. 从视频中提取音频
4. 将音频送入语音识别（ASR）服务，转为文字
5. 将"语音转写文字 + 视频文案"合并，送入大模型
6. 大模型按照预设提示词，输出结构化的食谱数据（JSON格式）
7. 前端渲染结果

**输出结构**（大模型返回的JSON格式）：

```json
{
  "title": "番茄炒蛋",
  "source_url": "原始链接",
  "source_platform": "小红书",
  "ingredients": [
    { "name": "鸡蛋", "quantity": "3个" },
    { "name": "番茄", "quantity": "2个" },
    { "name": "盐", "quantity": "适量" },
    { "name": "葱花", "quantity": "少许" }
  ],
  "steps": [
    { "step": 1, "content": "鸡蛋打入碗中，加少许盐，搅散备用" },
    { "step": 2, "content": "番茄洗净，切成小块" },
    { "step": 3, "content": "热锅倒油，油热后倒入蛋液，炒至凝固盛出" },
    { "step": 4, "content": "同一锅中加少许油，倒入番茄块翻炒出汁" },
    { "step": 5, "content": "倒回炒好的鸡蛋，加盐调味，翻炒均匀" },
    { "step": 6, "content": "出锅前撒上葱花即可" }
  ]
}
```

### 2.2 食材用量规则

- 原样保留博主的表达（"适量"、"少许"、"一小勺"等），不做AI估算
- 如果博主完全没提到某个食材的用量，标注为"未提及"

### 2.3 步骤颗粒度规则

- MVP阶段先保持原样不拆分复合动作，观察用户反馈后再决定是否加"细拆模式"

### 2.4 编辑修正功能

用户可以对解析结果进行以下编辑：
- 修改食材名称和用量的文字内容
- 修改步骤的文字内容
- 调整步骤顺序（拖拽或上下移动）
- 新增一个步骤
- 删除某个步骤
- 新增或删除某个食材

### 2.5 保存历史记录

- 解析完成后自动保存到"我的菜谱本"
- 菜谱本以列表形式展示，每条记录显示：菜名、来源平台图标、保存时间
- 点击可查看完整食谱详情
- 支持手动删除某条记录

### 2.6 做饭模式

- 从食谱详情页进入"做饭模式"
- 一次只显示当前这一步（卡片式），大字体方便做饭时看
- 显示当前步骤序号和总步骤数（如"第3步 / 共6步"）
- 底部有"上一步""下一步"按钮
- 当前步骤可以勾选"已完成"打卡
- 所有步骤完成后显示"恭喜完成！"

## 四、技术方案

### 4.1 整体架构

```
微信小程序（前端）
    ↕ HTTPS请求
Python后端服务（Flask / FastAPI）
    ↕ 调用各API
┌─────────────────────────────────────┐
│  ① 视频解析API（获取视频地址+文案）    │
│  ② 音频提取（ffmpeg，在后端服务器运行） │
│  ③ 语音识别API（阿里云/腾讯云ASR）     │
│  ④ 大模型API（DeepSeek/通义千问）      │
└─────────────────────────────────────┘
```

### 4.2 前端：微信小程序

- **框架**：原生微信小程序（WXML + WXSS + JS），或使用uni-app（可后续跨平台）
- **本地存储**：使用微信小程序的 `wx.setStorageSync` 存储菜谱历史记录（MVP阶段不需要数据库，本地存储足够几百条菜谱）
- **无需用户登录/注册**：MVP阶段数据全部存在用户本地

### 4.3 后端服务

- **语言**：Python
- **Web框架**：FastAPI（推荐，异步支持好、自带API文档）或 Flask
- **部署**：云服务器（推荐腾讯云/阿里云的轻量应用服务器，最低配大约50-80元/月），需要安装ffmpeg
- **核心逻辑**：一个HTTP接口，接收视频链接，依次调用下面4个步骤，返回结构化JSON
- **域名**：需要一个已备案的域名（微信小程序要求所有请求域名必须备案），备案大约需要1-2周

### 4.4 第三方API选型

**① 视频解析（链接 → 视频地址 + 文案）**
- 方案：使用付费的"无水印视频解析"API服务（如TiKhub、皮皮虾去水印等类似API）
- 费用：通常几分钱到一两毛/次
- 输入：视频分享链接
- 输出：无水印视频直链 + 视频标题/文案
- 备选：B站可用官方API（免费、稳定），小红书和抖音需要用第三方解析服务

**② 音频提取（视频 → 音频）**
- 方案：在后端服务器上用ffmpeg
- 费用：免费（ffmpeg是开源工具）
- 流程：先下载视频到服务器临时目录 → ffmpeg提取音频为mp3 → 处理完成后删除临时文件
- Python调用方式：`subprocess.run(["ffmpeg", "-i", "video.mp4", "-vn", "audio.mp3"])`

**③ 语音识别（音频 → 文字）**
- 推荐：阿里云语音识别（Paraformer模型）或腾讯云ASR
- 费用：阿里云新用户有免费额度，之后大约几分钱/分钟
- 输入：音频文件URL或文件本身
- 输出：识别出的文字（含时间戳）
- Python SDK：`pip install alibabacloud-nls` 或腾讯云对应SDK

**④ 大模型结构化整理（原始文字 → 食谱JSON）**
- 推荐：DeepSeek API（便宜、中文能力强）或阿里通义千问API
- 费用：极低，一次菜谱文本的token量很小，大约几厘到几分钱/次
- 输入：语音转写文字 + 视频文案 + 提示词
- 输出：结构化食谱JSON
- Python调用方式：`import openai`（DeepSeek兼容OpenAI接口格式）

### 4.5 大模型提示词（核心，需要反复调优）

```
你是一个专业的食谱整理助手。我会给你一段菜谱视频的语音转写文字和视频文案，
请你从中提取以下信息，以JSON格式输出：

1. title: 这道菜的名称
2. ingredients: 食材清单，每个食材包含 name（名称）和 quantity（用量）。
   用量保留原话（如"适量"、"少许"、"一小勺"），
   如果完全没提到用量则填"未提及"。
3. steps: 分步骤的教程，每一步包含 step（序号）和 content（具体操作描述）。
   步骤按实际烹饪顺序排列，每步描述一个完整的操作动作。

要求：
- 只输出JSON，不要其他解释文字
- 如果语音转写和文案中有矛盾，以内容更详细的一方为准
- 步骤描述用简洁的祈使句
- 不要发明原文没提到的食材或步骤

语音转写内容：
{asr_text}

视频文案：
{caption_text}
```

### 4.6 后端API接口设计

**唯一的核心接口**：

```
POST /api/parse-recipe

请求体：
{
  "url": "https://v.douyin.com/xxxxx"
}

响应体（成功）：
{
  "success": true,
  "data": {
    "title": "番茄炒蛋",
    "source_url": "...",
    "source_platform": "抖音",
    "ingredients": [...],
    "steps": [...]
  }
}

响应体（失败）：
{
  "success": false,
  "error": "不支持的链接格式" / "视频解析失败" / "语音识别失败" / ...
}
```

### 4.7 后端核心代码结构（Python）

```
recipe-backend/
├── main.py                # FastAPI入口，定义路由
├── services/
│   ├── link_parser.py     # 识别链接平台 + 调用视频解析API
│   ├── audio_extractor.py # 下载视频 + ffmpeg提取音频
│   ├── speech_to_text.py  # 调用ASR语音识别
│   └── recipe_extractor.py# 调用大模型 + 提示词 → 结构化JSON
├── config.py              # API密钥、配置项
├── requirements.txt       # 依赖包
└── README.md
```

## 五、开发计划（建议分阶段）

### 阶段一：后端核心（预估3-5天）
- 搭建Python FastAPI后端服务，实现 `/api/parse-recipe` 接口
- 接通视频解析API、ffmpeg音频提取、ASR、大模型
- 用Postman或命令行测试，确认链接输入后能正确返回结构化JSON
- 先只做一个平台（建议先做B站，API最友好），跑通后再加抖音和小红书

### 阶段二：小程序前端（预估5-7天）
- 首页：输入框 + 解析按钮 + 最近菜谱列表
- 解析结果页：食材清单 + 步骤列表
- 我的菜谱本：历史记录
- 本地存储逻辑

### 阶段三：编辑与做饭模式（预估3-5天）
- 编辑功能：修改文字、增删步骤/食材、调整顺序
- 做饭模式：单步卡片UI、上下步切换、勾选打卡

### 阶段四：上线（预估1-2周，主要等备案）
- 域名ICP备案
- 微信小程序审核提交
- 上线后观察、调优提示词

## 七、风险与待办

1. **视频解析API的稳定性**：小红书和抖音的第三方解析服务可能随时因平台反爬策略变化而失效，需要有"解析失败时的兜底提示"，并做好更换API供应商的准备
2. **微信小程序审核**：提交审核时说明是"个人菜谱笔记工具"，不要强调"提取其他平台内容"，降低被拒风险
3. **提示词调优**：大模型提取食材和步骤的准确度高度依赖提示词质量，上线后需要根据实际解析结果持续调整
4. **步骤颗粒度**：MVP先不拆分复合动作，观察用户反馈后再决定
5. **域名备案**：提前启动，通常需要1-2周，是上线的关键路径
